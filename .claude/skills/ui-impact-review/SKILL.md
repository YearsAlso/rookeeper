# UI Impact Review — 协议/CLI 影响分析

当 `crates/rookeeper-server/src/` 或 `crates/rookeeper-cli/src/` 下文件发生变更时，分析协议/CLI 变动对客户端和用户的影响，以清晰直观的方式输出设计建议。reviewer 在 Server/CLI 相关变更时附加调用本 skill。

## 硬约束

- **严禁修改任何代码文件**（本 skill 只有只读分析能力）
- **严禁提供超出架构/协议范畴的建议**（不涉及后端核心逻辑、存储、安全）
- **严禁自行脑补需求**（不确定时标注"需与产品确认"）
- **只做协议/CLI 设计建议**，输出到审查报告，由主 Agent/开发者决定是否采纳

## 变更分析维度

### 1. 协议帧格式变动
- 新增/删除/修改了帧头部字段 → 客户端和服务端需要同步解析逻辑
- 请求/事件类型变更（`RequestKind`/`EventKind` 枚举）→ 客户端需要更新匹配逻辑
- 帧头长度变化（`FRAME_HEADER_LEN` 常量）→ 二进制兼容性破坏

### 2. CLI 命令变动
- 新增/删除/修改了子命令 → 用户文档、脚本集成需要更新
- 命令参数变化（新增必填参数、参数重命名）→ 用户脚本、CI 管道需要同步
- 输出格式变化（JSON/纯文本）→ 用户解析逻辑需要调整

### 3. 配置结构变动
- 新增/删除/修改了配置字段（`ServiceConfig` 子结构）→ 用户配置文件需要更新
- 配置默认值变化 → 用户行为可能受影响
- 配置路径变化（`config/rookeeper.default.toml`）→ 部署脚本需要调整

### 4. 错误码与行为变动
- 新增错误码（`ErrorCode` 枚举）→ 客户端错误处理需要扩展
- 错误消息格式变化 → 用户日志解析规则需要调整
- 超时/重试行为变化 → 用户客户端策略需要同步

## 执行流程

1. **识别变更范围**：读取变更文件，提取涉及的模块名称和变更类型（新增/修改/删除）
2. **按模块分析**：对每个变更的模块，分析其帧格式/命令/配置/错误码变化
3. **输出影响建议报告**（Emoji 化格式）：


## 工作约束

- 不修改任何代码文件
- 不涉及后端核心逻辑、存储、安全审查
- 每个建议标注影响程度：🔴 必须 / 🟡 建议 / 🟢 可选
- 不确定的判断标注"需与产品/客户端确认"
- 如 Server/CLI 文件夹无变更，回复"✅ 无协议/CLI 相关变更，跳过分析"
