# Security Review — 安全审查

审查 rookeeper 项目的安全漏洞和工业控制环境安全风险。reviewer 在审查 `**/*.rs` 变更及提交前安全闸门（PreToolUse）时调用本 skill。

## Ollama 两级协作

> 机械预审复用 `/ollama-call` skill（探测命令、超时、回退逻辑见该 skill，此处为执行摘要）。

**Ollama 可承担**（模式匹配类）：
- 硬编码凭据（密钥、Token、密码字符串）
- 未处理的 `unwrap()`、`expect()`、`panic!()` 宏
- 缺少 `#[serde(deny_unknown_fields)]` 的配置结构
- 日志中泄露敏感信息
- 缺少 `// SAFETY:` 注释的 unsafe 块

**Claude 必须做**（不可委托）：
- 路径遍历分析（NodePath 的 `..` 防护，需要理解业务上下文）
- 工业控制环境安全（单实例锁、数据完整性、恢复安全）
- TOCTOU 竞争条件（文件系统操作、并发访问）
- 内存安全（unsafe 块的正确性验证）
- 任何需要 file:line 精确引用的技术断言

**执行流程**：
```
1. curl -s --connect-timeout 3 --max-time 5 localhost:11434/api/tags
   ├─ 200 → Ollama 可用：发送 git diff(≤300行) 做机械安全扫描
   │   ├─ 返回 CLEAN → 跳过机械检查，仅做语义审查
   │   └─ 返回 N 条 RED_FLAG/WARNING → RED_FLAG 转入必查项
   └─ 其他 → 跳过，完整 6 维度审查
2. Claude 逐条验证 Ollama 发现（过滤误报）
3. Claude 独立审查语义级安全问题
4. 合并输出，Ollama 发现的标记 [Ollama]
```

**质量门禁**：RED_FLAG 必须逐条验证确认后才纳入报告；WARNING 仅作参考线索；误报过滤后不输出。

## 审查维度

### 1. 路径遍历与数据安全
- NodePath 是否正确拒绝 `..` 父路径遍历
- 路径输入是否经过 `NodePath::parse` 规范化，而非手动处理反斜杠
- 存储路径是否通过 `StorageLayout` 统一管理，禁止硬编码路径
- 文件操作是否验证路径安全性（防止符号链接攻击）

### 2. 不安全代码与内存安全
- `unsafe` 块是否都有 `// SAFETY:` 注释说明前提条件
- 裸指针操作是否验证非空、对齐、别名条件
- FFI 边界是否使用 `#[repr(C)]` 确保内存布局兼容
- 是否存在未初始化的内存（`MaybeUninit` 使用是否正确）
- 引用是否在 unsafe 块中保持有效（生命周期不超出借用来源）

### 3. Panic 风险与错误处理
- 生产代码是否存在 `unwrap()`、`expect()`、`panic!()`、`unreachable!()`
- `Result` 返回值是否被正确处理（未被 `let _ =` 静默忽略）
- `?.context()` 是否提供了有意义的错误上下文
- 整数运算是否存在溢出风险（使用 `checked_`/`wrapping_` 方法，或 `#[allow(arithmetic_overflow)]` 合理性）

### 4. Serde 安全与数据验证
- 反序列化结构是否有 `#[serde(deny_unknown_fields)]` 防止未知字段注入
- 枚举反序列化是否使用 `#[serde(tag = "...")]` 或 `#[serde(untagged)]` 明确标记
- 大型载荷是否有限制（防止 `serde` 拒绝服务攻击）
- 二进制协议帧头 `payload_len` 是否在校验范围内（防止缓冲区溢出）

### 5. 并发与竞争条件
- 文件锁（`fs2` crate）使用是否正确，是否有超时机制
- 共享状态访问是否通过 `Mutex`/`RwLock` 保护
- 是否存在 TOCTOU（Time-of-check Time-of-use）竞争条件
- `tokio::sync` 原语使用是否正确（无死锁风险）

### 6. 工业控制环境安全
- 单实例锁是否防止多进程同时操作同一数据目录
- 状态机是否确定性（不依赖外部时间/随机数作为决策输入）
- WAL 写入是否原子性（写入前校验、写入后验证）
- 数据恢复过程是否验证完整性（CRC32 校验）
- 配置中敏感信息（Token 文件路径）是否有合理的文件权限要求

## 输出格式

```
## 安全审查报告

### 风险等级
- 🔴 高危（必须修复）：...
- 🟡 中危（建议修复）：...
- 🔵 低危（注意）：...
- ✅ 通过：...

### 各维度检查
1. 路径遍历与数据安全：✅ / 🔴 ...
2. 不安全代码与内存安全：✅ / 🔴 ...
3. Panic 风险与错误处理：✅ / 🔴 ...
4. Serde 安全与数据验证：✅ / 🔴 ...
5. 并发与竞争条件：✅ / 🟡 ...
6. 工业控制环境安全：✅ / 🔴 ...

### 详细发现
| 文件:行号 | 风险等级 | 问题描述 | 修复建议 |
|-----------|---------|---------|---------|
```

## 工作约束

- 审查时不修改代码，只输出安全审查报告
- 每个发现必须标注：`文件:行号` + 风险等级 + 问题描述 + 修复代码示例
- 高危问题必须给出可直接替换的安全修复代码
- 不产生误报（不确定的标记"需人工确认"）
