# PM Memory — 产品经理记忆

维护 rookeeper 项目的产品经理（PM）记忆库 `docs/memory/pm-memory.md`。由 `pm` agent 专职维护（reviewer 审查发现文档差异/SDD 合规结论后转交）；software-engineer 编码前应读取记忆了解需求上下文与用户偏好。

## 触发时机

- docs-consistency-review 审查后产生文档差异/一致性结论
- 需求评审完成（需求上下文、范围边界确定）
- SDD 合规检查发现流程问题
- 用户表达明确的偏好/约束（影响后续开发决策）

## 记忆文档结构（docs/memory/pm-memory.md）

```
# 产品经理记忆

## 需求上下文
### {需求/模块名}
- 背景：{业务背景}
- 范围：{包含/不包含}
- 用户偏好/约束：{明确表达过的偏好}

## 文档一致性历史
- {yyyy-MM-dd}：{差异描述} → 处理：{更新文档/修复代码/需确认}（涉及文件）

## SDD 合规记录
- {yyyy-MM-dd}：{变更} → {合规/违规} {说明}

## Spec 台账
| Spec | 状态 | 关联变更 | 归档日期 |
|------|------|---------|---------|
| specs/<name>/ | 进行中/已归档 | ... | ... |

## 变更影响记录
- {yyyy-MM-dd}：{变更} → 影响 {文档/FDA合规/schema/API契约}
```

## 执行流程

### Step 1: 读取现有记忆
读取 `docs/memory/pm-memory.md`，了解既有需求上下文与差异历史，**避免重复记录**。

### Step 2: 判断记录价值
仅记录**影响后续决策**的信息：
- 需求范围边界、用户明确偏好 → 记录
- 文档-代码差异及其处理结论 → 记录（防止重复争议）
- 一次性执行细节 → 不记录

### Step 3: 追加记录
- 新需求上下文 → 追加到"需求上下文"
- 差异结论 → 追加到"文档一致性历史"
- 新 spec → 追加到"Spec 台账"

### Step 4: 输出确认
```
## PM 记忆已更新
- 新增：{条目类型}：{内容摘要}
```

## 工作约束

- 只维护 `docs/memory/pm-memory.md`，不修改其他文档
- 记录必须真实基于本次审查/需求，禁止虚构
- 用户偏好只记录**用户明确表达**的内容，不推断
- 若本次无新增内容，仅输出："✅ 无新增 PM 记忆，无需更新"
