# Doc Template — 文档编写规范

rookeeper 项目的文档编写规范。**强制流程：编写/更新任何文档前，先检查 `docs/template/` 下是否有匹配的文档模板；有模板则按模板结构生成，无模板则提示并建议创建**。

## 使用场景

- **设计阶段**：产出 `specs/<name>/spec.md`、`specs/<name>/design.md`
- **编码阶段**：software-engineer 编码后同步更新 `docs/` 受影响文档（接口/数据库/架构）
- **任何文档编写**：README、变更说明、设计文档等

## 模板映射表

| 文档类型 | 模板文件（docs/template/） | 适用产出 |
|---------|---------------------------|---------|
| 接口文档 | `接口文档模板.md` | API 路径、请求/响应、认证、错误码 |
| 数据库设计 | `数据库设计模板.md` | 表结构、字段、索引、FK、RULE |
| 技术架构/方案 | `技术架构模板.md` | 分层、依赖、关键模式、合规路径 |
| Spec 规范 | `Spec模板.md` | specs/<name>/spec.md + design.md |

## 强制流程

### Step 1: 检查模板
编写/更新文档前，先执行：
```bash
ls docs/template/
```
判断是否存在与文档类型匹配的模板文件。

### Step 2: 按模板生成（有模板）
- 打开对应模板，按模板的章节结构填写内容
- 模板中的占位符（如 `{接口路径}`、`{表名}`）必须全部替换为实际内容
- 不保留模板示例数据（示例仅作格式参考）
- 若模板与实际文档类型不完全匹配，按模板主结构编写并在结尾说明偏差

### Step 3: 无模板处理（无模板）
- 不自行编造结构，先提示用户："⚠️ docs/template/ 下无 {文档类型} 模板，建议先创建模板（可参考 docs/ 下现有 {同类文档}）"
- 如需立即编写，参考 `docs/` 下现有同类文档的结构编写，并建议后续补充模板

### Step 4: 更新映射表
若创建了新的模板，同步更新 `docs/template/README.md` 的映射表。

## 模板编写规范（创建新模板时）

- 模板使用 `{占位符}` 标注需填写位置
- 章节结构可复用现有 docs/ 文档的成熟结构（接口文档、数据库设计文档等）
- 模板必须包含：用途说明、章节结构、填写示例
- 每个模板文件头注释说明适用场景

## 与 docs-consistency-review 的关系

- 本 skill 管"怎么写文档"（结构规范）
- `docs-consistency-review` 管"文档与代码是否一致"（内容校验）
- software-engineer 编码时同步更新 docs/ 必须遵循本 skill；reviewer 审查时用 docs-consistency-review 验证结果

## 工作约束

- 编写文档必须按模板结构，禁止自由发挥结构
- 文档内容必须与代码实际行为一致，禁止虚构未实现功能
- 更新模板映射表只改 `docs/template/README.md`
