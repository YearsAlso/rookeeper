## 1. 文档目的与范围

本 BRD 旨在从商业视角阐述 **工控单机协调服务（rookeeper）** 的产品定位、市场机会、商业模式、定价策略、竞争优势与 12 个月商业目标。

本 BRD 与 PRD（产品需求文档）、MRD（市场需求文档）的关系如下：

```
MRD（市场与需求调研）
  └── 验证市场规模、用户痛点、竞品现状
           ↓
PRD（产品需求定义）
  └── 明确功能范围、优先级、技术边界
           ↓
BRD（商业需求映射）
  └── 将产品能力转化为可防御的商业模式、收入模型与市场策略
```

**关键假设**：V1.0 定位为"单机版 Firebase"，即面向工业设备内多进程提供本地协调能力（KV 存储、服务发现、锁、Watch），不依赖云端，不做多机分布式。

## 2. 产品愿景与战略定位

### 2.1 问题陈述

工业现场存在大量**单机多进程协调**需求，现状是：

- **PLC / 工控机内**：多个控制程序、驱动模块、边缘代理需要共享配置、互相发现、协同加锁，但缺乏统一协调层
- **现有方案缺陷**：ZooKeeper 过于重量（依赖 JVM、GC 停顿、复杂集群运维）；Redis 无协调语义；自研方案碎片化且不可维护
- **结果**：开发者被迫在每个应用中硬编码协调逻辑，引入大量隐式依赖和难以排查的竞态条件

### 2.2 产品愿景

> **"单机版 Firebase"——为每一台工业设备提供一个确定性、轻量、可恢复的本地协调平面。**

我们重新定义产品定位：**不是 ZooKeeper 的简化版，而是面向工控单机场景的原生协调内核**。

| 维度 | Firebase（云） | rookeeper（本地） |
| --- | --- | --- |
| 部署形态 | 云服务 | 嵌入式二进制 |
| 网络依赖 | 必须联网 | 完全离线 |
| 场景 | 移动/Web 应用 | 工业设备、工控机、边缘网关 |
| 协调语义 | 有限 | 完整（KV、锁、Watch、注册发现） |
| 延迟 | 依赖网络 RTT | 微秒~低毫秒本地 IPC |

### 2.3 战略意义

1. **工控 Rust 基础设施空白填补**：国内无成熟开源工控协调内核，rookeeper 有机会成为该赛道的定义者
2. **工控软件平台化入口**：单机协调服务是工控设备管理平台的前置依赖，后续可延伸至边缘管理、OTA、诊断等高价值场景
3. **国际化开源品牌**：纯 Rust 实现，技术差异化强，适合打造国际化开源品牌

- **竞争真空**：国内无开源竞品；ZooKeeper/Etcd 不适合工控单机场景

## 4. 商业模式分析

### 4.1 三种路径对比

| 模式 | B2B 授权（一次性/年度） | 开源免费 + 企业版 | SaaS（云端控制面） |
| --- | --- | --- | --- |
| **核心逻辑** | 向设备 OEM / 集成商卖软件授权 | 开源引流，企业版提供附加能力 | 提供云管理平台，按设备订阅收费 |
| **优势** | 收入可预测，壁垒强 | 社区传播快，降低信任成本 | 边际成本低，可持续收费 |
| **劣势** | 销售周期长，渠道依赖重 | 企业版营收能力不确定 | 工控场景 SaaS 接受度存疑（离线优先） |
| **定价参考** | $50-$200/设备/年 | 社区免费；企业版 $2,000-$20,000/年 | ¥30-80/设备/月 |
| **适合场景** | 标准化工业设备大批量出货 | 技术社区、ISV、平台公司 | 边缘管理平台、远程运维场景 |
| **风险** | 需建立直销/渠道网络 | 开源后商业化路径不清晰 | 离线场景 SaaS 价值有限 |

### 4.2 推荐模式：**分阶段混合策略**

```
Phase 1（V1.0 上市后 12 个月）：以开源为核心，建立生态
├── 开源核心功能（单机 KV + Watch + 锁 + WAL 恢复）
├── 企业版：高级插件（OPC UA、MQTT、远程管理、 SLA 支持）
└── B2B 授权：针对 OEM 大客户定制打包

Phase 2（12-24 个月）：企业版 + OEM 授权双轮驱动
├── 推出分布式版（多节点协调）
├── 企业版扩展为完整边缘管理平台
└── 战略级 OEM 合作（年框协议）
```

**推荐理由**：工控行业决策链长、付费习惯保守，开源策略可快速建立市场认知与开发者口碑；企业版提供差异化高价值能力；B2B 授权覆盖战略大客户。

## 5. 定价策略

### 5.1 分层定价框架

| 层级 | 目标用户 | 定价 | 包含能力 |
| --- | --- | --- | --- |
| **社区版（Open Source）** | 开发者、研究者、评估阶段 | 免费 | 核心 KV、WAL、Watch、单进程锁、基本 CLI |
| **企业版（Standard）** | 中小型工业软件商、集成商 | ¥6,000 - ¥18,000 / 年 | 社区版全部 + 多进程锁、ACL、录制回放、JSON 指标、本地 TCP |
| **企业版（Professional）** | 大型集成商、OEM 厂商 | ¥30,000 - ¥80,000 / 年 | 企业版全部 + OPC UA/MQTT 插件、高级热冷分层、优先支持、SLA |
| **战略授权（Custom）** | 设备 OEM、战略大客户 | 单独谈判 | 企业版全部 + 定制功能、技术支持、培训、源代码授权 |

### 5.2 定价维度说明

| 维度 | 选项 | 分析 |
| --- | --- | --- |
| **按设备计价** | 每台设备一个授权 | 最简单，适合 OEM 大批量；但无法区分设备价值差异 |
| **按节点数计价** | 按设备上的进程/节点数分级 | 更精细，但计量复杂，用户理解成本高 |
| **按能力分级** | 社区/标准/专业三个功能层级 | 符合软件行业惯例，降低决策门槛 |
| **按部署规模** | 按设备内存/CPU 规格分级 | 不推荐，工控场景设备规格差异大，计量成本高 |

**推荐**：**按能力分级（功能层级）+ 附加设备数授权**的混合模式

```
基础授权（按设备数）：¥600 - ¥1,800 / 设备 / 年
升级包（按功能层级）：企业版 Standard / Professional 叠加收费
```

### 5.3 定价心理锚点

- **参照物**：商业级 ZooKeeper 发行版（年费 $5,000-$20,000）；Redis Enterprise（按节点 $2,000+/年）
- **锚定策略**：rookeeper 以"更低价格 + 工控场景原生适配"切入，为客户节省 50-70% 的 ZooKeeper 类方案成本

## 6. 竞争优势分析

### 6.1 竞争格局

```
                    云端依赖
                        ↑
                        |
         其他方案       |
    （自研/碎片化）     |
                        |
  ─────────────────────────────────────→
           轻量/重用 ←──────→ 功能丰富
                        |
                        ↓
              ┌─────────────────┐
              │   rookeeper    │ ← 目标定位
              │ （工控原生+轻量）│
              └─────────────────┘
```

### 6.2 核心竞争优势

| 维度 | rookeeper | Firebase（云） | Redis | ZooKeeper |
| --- | --- | --- | --- | --- |
| **部署形态** | 本地嵌入式二进制 | 云服务 | 本地/云 | 集群部署 |
| **协调能力** | 完整（KV+锁+Watch+注册发现） | 有限（数据库+推送） | 无协调语义 | 完整但偏分布式 |
| **工控适配** | 原生（Rust、无 GC、跨平台） | 不适配 | 无协调语义 | JVM 重量级、GC 停顿 |
| **离线运行** | ✅ 完全离线 | ❌ 需联网 | ✅ 可离线 | ✅ 可单机 |
| **断电恢复** | ✅ WAL+快照，亚秒级 | N/A | 依赖配置 | 较慢 |
| **资源占用** | < 20MB 内存 | N/A（云端） | 中等 | JVM + 内存 |
| **学习曲线** | 低（单一二进制） | 低（SDK 友好） | 低 | 高（集群运维复杂） |
| **定制成本** | 开源可控 | 黑盒不可改 | 可定制 | 可定制 |
| **目标场景** | 工业设备单机协调 | 移动/Web 应用 | 缓存 | 分布式协调 |

### 6.3 差异化壁垒

1. **工控原生适配**：Rust 实现 + 无 GC 停顿 + 跨平台（Linux/Windows）+ 微秒级延迟，远优于 JVM 方案
2. **离线协调能力**：Firebase 等云端方案无法满足工业现场的离线优先需求
3. **确定性恢复**：基于确定性状态机的 WAL+快照方案，比通用数据库/消息队列更可预测
4. **开源先发优势**：国内无直接竞品，有机会成为工控协调领域的定义者
5. **演进路径清晰**：单机版设计即为分布式版的前置阶段，客户投资可持续

1. **开源发布质量**：首个版本需稳定、文档完整、示例可运行，避免早期负面口碑

3. **社区运营**：建立 QQ/微信开发者群、技术博客、示例代码，降低开发者入门门槛
4. **渠道建设**：发展工业软件集成商作为转售渠道，OEM 厂商作为战略客户
